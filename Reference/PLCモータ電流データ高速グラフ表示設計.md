# PLCモータ電流データの高速グラフ表示設計

## ― PLC通信実測値と pywebview + Chart.js の表示時間予測 ―

作成日: 2026-08-09

------------------------------------------------------------------------

## 1. 目的

設備のモータ電流値をキーエンス KV-5000
からPCへ取得し、Pythonアプリ上で高速に波形表示する。

想定構成は次のとおり。

``` text
KEYENCE KV-5000
    ↓ 上位リンク通信
Python
    ↓
pywebview
    ↓
JavaScript
    ↓
Chart.js
    ↓
モータ電流波形を表示
```

本資料では、実機で測定したPLC通信時間を基準として、

-   PLCからのデータ受信
-   Python側でのデータ処理
-   PythonからJavaScriptへの受け渡し
-   Chart.jsによる5000点のグラフ描画

までを含めた、実際の画面表示までの時間を予測する。

今後、モータ電流監視・異常検知・波形表示アプリを設計する際の基準資料として使用する。

# 3. 2ワード × 5000点の通信時間

モータ電流データは1点あたり2ワード（32bit）として扱う。

5000点の場合、

``` text
2ワード × 5000点
= 10000ワード
```

相当のデータを取得することになる。

今回の通信モジュールでは32bitデータを500点ずつ読み込むため、5000点では通信が10回に分割される。

``` text
5000点 ÷ 500点/回
= 10回
```

したがって、

``` text
10回 × 約20ms
≒ 約200ms
```

と概算できる。

実測値は次のとおりだった。

    測定   通信時間
  ------ ----------
       1   159.2 ms
       2   157.6 ms
       3   193.5 ms
       4   156.5 ms
       5   177.8 ms

平均値は約169msである。

したがって設計上は、

``` text
通常値       約160～180ms
安全側の目安 約200ms
```

として考えるのが妥当である。

------------------------------------------------------------------------

# 4. 通信速度から分かった重要なこと

今回の測定結果では、単純なデータ量だけではなく、**PLCとの通信回数の影響が大きい**ことが分かる。

たとえば、

``` text
1W × 1点       約4～15ms
1W × 1000点    約14～24ms
1W × 5000点    約81～96ms
2W × 5000点    約157～194ms
```

となっている。

1点と1000点ではデータ量が1000倍違うが、通信時間は1000倍にはなっていない。

一方、通信回数が増えると全体時間がかなり増加する。

そのためPLC通信を高速化するときは、

> 1回あたりのデータ量を極端に小さくするより、通信回数を減らすことが重要

と考えられる。

今回の環境では、

``` text
通信時間 ≒ 通信回数 × 20ms
```

を概算式として持っておくと、今後のシステム設計で便利である。

``` text

```

を想定しておく。

したがって目標としては、

> PLCの要求発生から約0.3秒前後でモータ電流波形を表示

が十分現実的と考えられる。

# 6. ボトルネックはどこか

今回の測定結果では、PLC通信だけですでに約160～200msを使用する。

一方、PythonからChart.jsまでの処理は、適切に実装すれば数十ms～100ms程度に収まる可能性が高い。

イメージは次のとおり。

``` text
PLC通信開始
    │
    ├─ PLCデータ受信            約160～200ms
    │
    ├─ Pythonデータ整形          約5～20ms
    │
    ├─ pywebview → JavaScript    約5～30ms
    │
    ├─ Chart.jsデータ設定・描画  約25～120ms
    │
    ├─ 画面反映                  約10～30ms
    │
    ▼
グラフ表示
```

したがって、現在の予測では**最大の時間要因はPLC通信**である。

たとえばChart.jsの処理を、

``` text
60ms → 30ms
```

まで高速化できたとしても、

``` text
PLC通信 200ms + 描画 60ms = 260ms
PLC通信 200ms + 描画 30ms = 230ms
```

という差になる。

もちろん画面側の最適化は重要だが、5000点程度の波形表示であれば、

> pywebview + Chart.js が致命的なボトルネックになる可能性は低い

と予測できる。

# 7. pywebview + Chart.js を採用する理由

今回の用途では、

``` text
Python
    ↓
5000点の数値データ
    ↓
pywebview
    ↓
JavaScript
    ↓
Chart.js
```

という構成が適している。

以前使用していたような、

``` text
Python
    ↓
matplotlib
    ↓
PNG画像生成
    ↓
Base64変換
    ↓
pywebview
    ↓
<img>で画像表示
```

という方法では、Python側でグラフを画像化する処理が必要になる。

さらに、

-   matplotlibで描画
-   PNG化
-   Base64化
-   HTMLへ転送
-   ブラウザで画像デコード
-   `<img>`として表示

という処理が発生する。

これに対してChart.js方式なら、Pythonから送るのは基本的に数値データだけでよい。

``` text
PLC
 ↓
Python list
 ↓
JavaScript Array
 ↓
Chart.js
```

この構成はシンプルであり、高速な波形更新にも向いている。

------------------------------------------------------------------------

# 8. Chart.js側の重要な高速化ポイント

## 8.1 Chartを毎回作り直さない

波形更新のたびに、

``` javascript
new Chart(...)
```

を実行してグラフそのものを作り直す方法は避ける。

毎回作り直すと、

``` text
既存Chartの破棄
    ↓
Chartオブジェクト生成
    ↓
軸生成
    ↓
5000点登録
    ↓
レイアウト計算
    ↓
描画
```

という処理が発生する。

基本方針は、**Chartオブジェクトを一度作成して再利用する**ことである。

たとえば、

``` javascript
chart.data.datasets[0].data = values;
chart.update("none");
```

のように、データだけを差し替える。

------------------------------------------------------------------------

## 8.2 アニメーションを無効化する

今回のグラフはモータ電流波形の確認が目的であり、表示時のアニメーションは不要である。

``` javascript
animation: false
```

を設定するか、

``` javascript
chart.update("none");
```

を使用して、更新アニメーションを行わない。

これにより、

``` text
データ受信完了
    ↓
即座に波形表示
```

という動作に近づけられる。

------------------------------------------------------------------------

# 9. Python → JavaScript のデータ受け渡し

5000点程度であれば、Python側で取得した数値を配列としてJavaScriptへ渡す方法が分かりやすい。

イメージ：

``` python
values = [
    123,
    125,
    128,
    130,
    # ...
]
```

これをJavaScript側でChart.jsのデータとして使用する。

今回の用途では、Python側で画像を作るのではなく、

> Pythonは数値データを取得・処理し、グラフ描画はJavaScriptに担当させる

という責務分担が適している。

# 11. 今後の性能測定で確認すべき項目

ここまでのうち、PLC通信については実測済みである。

一方、

-   Python側データ変換
-   pywebview経由のデータ転送
-   Chart.js描画
-   ブラウザへの最終反映

については予測値である。

アプリ実装後は、各ポイントで時刻を測定する。

``` text
T0 : PLCデータ受信開始
T1 : PLCデータ受信完了
T2 : Python側データ処理完了
T3 : JavaScriptへデータ受け渡し
T4 : Chart.js更新開始
T5 : Chart.js更新・画面反映完了
```

これにより、

``` text
PLC通信時間       = T1 - T0
Python処理時間    = T2 - T1
Python→JS転送時間 = T3 - T2
グラフ処理時間    = T5 - T3
全体時間          = T5 - T0
```

として測定できる。

予測だけで判断せず、最終的には実機・実アプリで測定することが重要である。

# 12. 今後の設計方針

現時点では、モータ電流波形表示について次の構成を標準方針とする。

``` text
┌─────────────────────┐
│ KEYENCE KV-5000     │
│ モータ電流 5000点   │
└──────────┬──────────┘
           │
           │ 上位リンク通信
           │ 約160～200ms
           ▼
┌─────────────────────┐
│ Python              │
│ ・PLC通信           │
│ ・データ整形        │
└──────────┬──────────┘
           │
           │ 数値配列
           ▼
┌─────────────────────┐
│ pywebview           │
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│ JavaScript          │
│ Chart.js            │
│ ・既存Chartを再利用 │
│ ・animationなし     │
└──────────┬──────────┘
           │
           ▼
      モータ電流波形
```

基本方針は、

1.  PLCデータはできるだけ少ない通信回数でまとめて取得する。
2.  Python側ではグラフ画像を生成しない。
3.  PythonからJavaScriptへ数値配列を渡す。
4.  グラフ描画はChart.jsに担当させる。
5.  Chart.jsのインスタンスは再利用する。
6.  グラフ更新時のアニメーションは無効化する。
7.  実装後に各処理区間を実測し、ボトルネックを確認する。

とする。

# 13. 結論

今回の実測では、2ワード × 5000点のPLC通信時間は、

``` text
約156～194ms
平均 約169ms
```

であった。

設計上は余裕を見て、

``` text
PLC通信 約200ms
```

と考える。

その後のPython処理、pywebviewによるJavaScriptへのデータ受け渡し、Chart.js描画を含めると、

``` text
通常       約250～350ms
余裕を見て 約350～500ms
```

程度で画面表示できる可能性が高い。

したがって、

> **5000点のモータ電流波形を、PLCから受信して約0.3秒前後で画面表示する**

ことを現実的な目標とする。

また今回の通信速度測定から、

> **通信データ量だけでなく、PLCとの通信回数が全体時間に大きく影響する**

ことが確認できた。

今後の高速データ収集では、通信回数を抑える設計を優先する。

画面表示については、5000点程度であれば `pywebview + Chart.js`
を第一候補とし、Pythonはデータ取得・処理、JavaScriptは描画という役割分担を基本とする。
