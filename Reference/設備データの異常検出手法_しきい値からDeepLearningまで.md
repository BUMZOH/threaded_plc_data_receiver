# 設備データの異常検出手法

## ― しきい値・統計・古典的機械学習・Deep Learning の特徴と選定方針 ―

## 1. はじめに

現在開発中の「設備データ受信アプリ」では、PLCから計測データを受信し、そのデータを画面へ表示するとともにSQLiteへ保存し、判定結果をPLCへ通知する構成になっている。

対象データとして、モータ電流値、サーボモータトルク値、スピンドル回転数、機械振動などを想定している。

現在の `judge_data(values)` は常に `True`
を返す仮実装である。一方、受信処理側では `judge_data()`
の結果によってOK/NGを決定し、画面表示・SQLite保存・PLCへの判定通知を行う流れがすでに作られている。

したがって今後は `judge_data()`
を発展させることで、「設備データ受信アプリ」から「設備状態を自動判定するアプリ」へ発展させることができる。

異常検出では「何でもAIで解決する」のではなく、問題に応じて次の段階から適切な方法を選ぶことが重要である。

1.  単純なしきい値
2.  統計的手法
3.  古典的機械学習
4.  Deep Learning

高度な方式ほど必ず優れているわけではない。設備診断では精度だけでなく、判定理由の説明性、調整・保守の容易さ、学習データを準備できるかどうかも重要である。

## 2. 各方式の比較

  --------------------------------------------------------------------------------------------------------------------
  方法             代表例                         学習データ   説明しやすさ    実装難易度 向いているケース
  ---------------- ------------------------ ---------------- -------------- ------------- ----------------------------
  しきい値         最大値、平均値、範囲                 不要              ◎             ◎ 異常条件が明確

  統計的手法       標準偏差、Z-score、IQR     主に正常データ              ◎             ○ 正常範囲からの逸脱

  古典的機械学習   Isolation Forest、SVM等              必要              ○             △ 複数特徴量を組み合わせたい

  Deep Learning    Autoencoder、1D-CNN等          大量に必要           △～×             × 波形自体に複雑な特徴がある
  --------------------------------------------------------------------------------------------------------------------

基本的には **しきい値 → 統計 → 古典的機械学習 → Deep Learning**
の順に検討し、単純な方法で解決できない場合に次の段階へ進む考え方が適している。

## 3. 単純なしきい値による異常判定

最も基本的な方法である。例えばモータ電流について最大値が5000を超えたらNGとするなら、概念的には次のようになる。

``` python
if max(values) > 5000:
    return False
```

設備の物理仕様や経験から異常条件が明確なら、この方法は非常に強力である。

例えば「このモータは80Aを超えてはいけない」「このサーボのトルクは30N·m以内でなければならない」と分かっているなら、AIに学習させる必要はない。

### しきい値として利用できるもの

最大値だけではない。

-   最大値
-   最小値
-   平均値
-   Peak-to-Peak（最大値－最小値）
-   一定値以上になった点数
-   一定値以上だった時間
-   波形の積分値
-   上昇時間
-   下降時間
-   ピーク位置
-   ピーク数

例えばモータ電流なら、

``` text
最大電流       < 100 A
平均電流       < 60 A
80 A超過時間   < 100 ms
```

のすべてを満たした場合だけOKとすることもできる。

### 長所

-   実装が簡単
-   処理が高速
-   学習データ不要
-   判定理由を説明しやすい
-   設備技術者が調整しやすい
-   従来のPLC判定ロジックと考え方が近い

設備では「なぜNGになったのか説明できる」ことが非常に重要である。

### 弱点

加工品種、速度、負荷、工具、温度、設備個体差などによって正常値自体が変化する場合、単純なしきい値だけでは対応しにくい。このような場合に統計や機械学習を検討する意味が出てくる。

## 4. 統計的な異常検出

固定値を人間が決める代わりに、正常データから正常範囲を求める考え方である。

例えば正常時の最大電流を1000回測定し、

``` text
平均値      = 42 A
標準偏差 σ  = 2 A
```

だったとする。

正常範囲を `平均 ± 3σ` とすると、

``` text
42 ± 3 × 2
= 36 ～ 48 A
```

となる。

「48A」という値を人間が直接決めるのではなく、**過去の正常データのばらつきから正常範囲を求める**ところが重要である。

## 5. Z-score

Z-scoreは「今回の値が正常平均から標準偏差何個分離れているか」を表す。

例えば、

``` text
正常平均 = 42
標準偏差 = 2
```

の場合、今回が43なら平均に近い。一方、55なら平均からかなり離れており、異常候補と考えられる。

統計的手法は計算量も小さく、数百～数千点程度のデータでも十分実用的である。

## 6. 生波形と「特徴量」

設備異常検出で非常に重要なのが **特徴量（feature）** である。

500点のモータ電流波形を、そのまま機械学習へ渡す必要はない。500点から次のような数値を計算できる。

-   平均値
-   最大値
-   最小値
-   標準偏差
-   RMS
-   Peak-to-Peak
-   ピーク位置
-   ピーク数
-   立ち上がり時間
-   波形面積

例えば、

``` text
500点の生波形
        ↓
    特徴量抽出
        ↓
最大値        82.3
平均値        35.2
RMS           41.8
標準偏差       8.7
Peak-to-Peak  67.5
ピーク位置     238
```

のように、500個の生データを少数の意味のある数値へ変換する。

## 7. なぜ特徴量が重要なのか

``` text
500点
 ↓
特徴量抽出
 ↓
5～20個程度の意味のある数値
```

へ変換すると、

-   人間が理解しやすい
-   統計処理しやすい
-   機械学習しやすい
-   必要な学習データ量を抑えやすい
-   異常原因を分析しやすい

という利点がある。

設備知識を使って良い特徴量を設計することは、AIモデルを複雑にすること以上に重要になる場合がある。

## 8. 古典的機械学習

特徴量を使えるようになると、古典的機械学習が利用しやすくなる。

例えば最大値、平均値、標準偏差、RMS、Peak-to-Peakという5特徴量を作る。

正常データが特徴量空間の一定範囲に集まっているなら、

``` text
正常データの集団

       ○ ○
    ○ ○ ○ ○
     ○ ○ ○
       ○

                    × ← 今回
```

のように、正常データの集団から大きく外れたデータを異常と判断できる。

## 9. Isolation Forest

設備異常検出で検討価値が高い手法の一つがIsolation Forestである。

特徴は、

-   正常データを大量に利用しやすい
-   異常データを大量に用意しなくても利用しやすい
-   計算が比較的軽い
-   Pythonではscikit-learnで実装できる
-   複数特徴量を同時に考慮できる

ことである。

設備では、

``` text
正常データ → 100,000件
異常データ → 20件
```

のような状況も珍しくない。

設備は本来、正常に稼働する時間が圧倒的に長い。故障しないことは設備としては良いが、機械学習では「異常データが集まらない」という問題になる。

そこで、

``` text
正常状態を覚える
      ↓
正常からどれだけ外れたかを見る
      ↓
異常と判断する
```

という考え方が設備異常検出と相性が良い。

## 10. 教師あり機械学習

正常・異常データが十分に存在するなら教師あり学習も利用できる。

例えば、

``` text
max    mean    RMS    std    P-P    judge
80.2   32.1    38.2   5.1    62.3   OK
79.8   31.8    37.9   5.3    61.8   OK
121.3  48.2    62.5  14.7   103.1   NG
```

というデータを用意し、

``` text
特徴量
  ↓
機械学習モデル
  ↓
OK / NG
```

と分類する。

候補として、

-   Random Forest
-   SVM
-   Logistic Regression
-   Gradient Boosting系
-   XGBoost系

などがある。

ただし重要なのは、**正しくラベル付けされた十分なNGデータがあること**である。

## 11. Deep Learning

古典的機械学習では、

``` text
500点の波形
      ↓
人間が特徴量を設計
      ↓
特徴量
      ↓
機械学習
```

とすることが多い。

Deep Learningでは、

``` text
500点の波形
      ↓
Deep Learning
      ↓
OK / NG
```

のように、生波形そのものから特徴を学習させることが可能になる。

つまり、**特徴量そのものをモデルに学習させる**。

時系列データの候補として、

-   1D-CNN
-   Autoencoder
-   LSTM
-   Transformer系

などがある。

## 12. Autoencoderによる設備異常検出

Autoencoderは設備異常検出で興味深いDeep Learning手法である。

正常波形を大量に学習させ、

``` text
正常波形
   ↓
Autoencoder
   ↓
正常波形を復元
```

させる。

正常データならモデルがよく知っているため、

``` text
入力波形 ≒ 復元波形
```

となることが期待できる。

異常波形では、

``` text
入力波形
       /\       /______/  \_____/  \____

復元波形
       /\    /______/  \__/  \________
             ↑
        入力と合わない
```

という状態になる可能性がある。

そこで **入力波形と復元波形の誤差**
を計算し、誤差が小さければ正常、大きければ異常候補とする。

正常データ中心で学習できるため、設備異常検出との相性が良い。

## 13. Deep Learningを最初から使わない理由

Deep Learningは強力だが、常に最適ではない。

-   大量の学習データが必要
-   学習環境が必要
-   モデル管理が必要
-   パラメータ調整が必要
-   判定理由を説明しにくい
-   設備条件変更時に再学習が必要になる可能性
-   単純なしきい値で解決できる問題には過剰

例えば「100Aを超えたら物理的に異常」という問題をDeep
Learningで解く意味はほとんどない。

**単純な方法では捉えられない異常がある場合にDeep
Learningを検討する**という順番が合理的である。

## 14. 機械振動データは少し特殊

機械振動では時間波形だけでなく周波数成分が非常に重要になる。

``` text
時間波形
   ↓
 FFT
   ↓
周波数スペクトル
```

として解析する。

回転機械では、

-   回転周波数
-   高調波
-   ベアリング由来の周波数
-   アンバランス
-   芯ずれ
-   共振

などによって特徴的な周波数成分が現れる場合がある。

振動では例えば、

-   RMS
-   Peak
-   Peak-to-Peak
-   Crest Factor
-   FFTピーク
-   特定周波数帯域のエネルギー

などを特徴量にできる。

したがって、

``` text
振動波形
   ↓
時間領域の特徴量
   +
FFTによる周波数特徴量
   ↓
統計判定 / 機械学習
```

という構成が有力であり、振動だから最初からDeep
Learningというわけではない。

## 15. 現在のアプリとの組み合わせ

現在のアプリは複数の測定対象を設定ファイルで管理している。

例：

``` text
ToolB_Cross_Torque
SpindleInverter_MotorCurrent
measurement3
```

将来的には測定対象ごとに判定方式を変えられる構造が適している。

``` text
                         ┌─ しきい値
                         │
PLC → データ受信 → judge_data()
                         │
                         ├─ 統計
                         │
                         ├─ Isolation Forest
                         │
                         └─ Deep Learning
```

現在は、

``` python
judge_data(values)
```

だが、将来的には、

``` python
judge_data(config, values)
```

として測定対象の設定も渡す方法が考えられる。

設定ファイルに、

``` json
{
    "name": "SpindleInverter_MotorCurrent",
    "judge_method": "threshold"
}
```

あるいは、

``` json
{
    "name": "Machine_Vibration",
    "judge_method": "isolation_forest"
}
```

のような項目を持たせれば、一つのアプリ内で測定対象ごとに異なる判定アルゴリズムを利用できる。

## 16. 推奨する開発ステップ

### 第1段階：しきい値

まず、

-   最大値
-   最小値
-   平均値
-   RMS
-   Peak-to-Peak

などを計算し、単純なしきい値でどこまで異常を分離できるか確認する。

### 第2段階：統計

正常データを大量に蓄積し、

-   平均
-   標準偏差
-   分布
-   正常範囲

を調査する。

「正常とはどのような状態なのか」を数値として把握する段階である。

### 第3段階：特徴量 + 古典的機械学習

``` text
生波形
  ↓
特徴量
  ↓
Isolation Forest等
  ↓
異常度
```

へ進む。

単純なしきい値では表現しにくい、複数特徴量の組み合わせによる異常を検出する。

### 第4段階：Deep Learning

特徴量を設計しても十分に正常・異常を分離できず、

**「波形を見ると違いがあるが、どの数値を特徴量にすればよいか分からない」**

という段階になったら、Autoencoderや1D-CNNなどを検討する。

## 17. SQLiteへ生波形を保存する重要性

現在のアプリではSQLiteへ、

-   `data_name`
-   `measured_at`
-   `judge`
-   `data`（BLOB）

を保存する構造になっている。

これは将来の異常検出開発に非常に有利である。

今は単純なしきい値でも、生波形を保存しておけば後から過去データを使って新しいアルゴリズムを検証できる。

``` text
現在
  ↓
しきい値で判定
  ↓
SQLiteへ生波形を大量保存
  ↓
正常・異常データが蓄積

将来
  ↓
蓄積データをPythonで解析
  ↓
統計的特徴を調査
  ↓
特徴量を設計
  ↓
Isolation Forest等を検証
  ↓
必要ならDeep Learningを検証
```

つまり現在のアプリは、異常判定アプリであると同時に
**将来のAI用データ収集基盤** と考えることができる。

## 18. 生データを残すもう一つの意味

将来アルゴリズムを変更したとき、

``` text
過去の生波形
     ↓
新しい judge_data()
     ↓
再判定
```

ができる。

「新しい判定方式を過去のデータへ適用したらどうなるか」を検証できるため、異常検出システムを段階的に改善しやすい。

## 19. データ種類ごとの最初の候補

### モータ電流値

-   最大値
-   平均値
-   RMS
-   Peak-to-Peak
-   一定電流以上の継続時間
-   波形面積

まずしきい値・統計から開始し、必要に応じてIsolation Forest等を検討する。

### サーボモータトルク値

-   最大トルク
-   平均トルク
-   RMS
-   正負方向の最大値
-   ピーク位置
-   一定トルク以上の継続時間
-   動作区間ごとの特徴量

動作工程が毎回ほぼ同じなら、正常波形との比較も有効になる可能性がある。

### スピンドル回転数

-   最大・最小回転数
-   指令値との差
-   安定時のばらつき
-   立ち上がり時間
-   指定回転数へ到達するまでの時間
-   回転数低下量

物理的な正常条件が比較的分かりやすいため、まずしきい値・統計から検討しやすい。

### 機械振動

-   RMS
-   Peak
-   Peak-to-Peak
-   Crest Factor
-   FFT
-   特定周波数成分
-   特定周波数帯域のエネルギー

振動では時間波形だけでなく周波数解析を重要な候補とする。

## 20. 「AIを使わない判断」も重要

異常検出では、

``` text
Deep Learning > 機械学習 > 統計 > しきい値
```

という単純な優劣関係はない。

「モータ電流が100Aを超えた」という物理的に明確な異常なら、しきい値が最も適切である。

一方、

``` text
最大値は正常
平均値も正常
RMSも正常
しかし波形全体を見ると何かがおかしい
```

という問題なら、機械学習やDeep Learningを検討する価値が高くなる。

選ぶべきなのは「最も高度なアルゴリズム」ではなく、

**対象の異常を最も単純かつ確実に検出できるアルゴリズム**

である。

## 21. 複数方式を組み合わせる

将来的には一つの方式だけに限定する必要もない。

``` text
① 安全上絶対に超えてはいけない値
        ↓
   固定しきい値

② 通常状態からのずれ
        ↓
   統計判定

③ 複数特徴量の組み合わせ
        ↓
   Isolation Forest

④ 複雑な波形異常
        ↓
   Deep Learning
```

という役割分担も考えられる。

単純な判定を捨ててAIへ全面移行するより、**明確な従来ロジックとデータ駆動型の異常検出を組み合わせる**方が実用的な場合が多い。

## 22. 次に学ぶべきテーマ

次の段階として特に重要なのは、

**「500点程度の時系列波形から、どのような特徴量を取り出せるか」**

である。

例えば、

``` text
values[0]
values[1]
...
values[499]
```

から、

``` text
max
min
mean
std
RMS
Peak-to-Peak
peak position
area
```

などをPythonで実際に計算する。

この処理を理解すると、

``` text
生データ
  ↓
特徴量
  ↓
統計
  ↓
機械学習
```

という流れが具体的に理解できる。

さらに、「特徴量を人間が作らず、波形からモデル自身に学習させる」というDeep
Learningとの違いも理解しやすくなる。

## 23. まとめ

今回の設備異常検出では、最初からAIやDeep Learningへ進む必要はない。

``` text
Level 1
単純なしきい値
      ↓
Level 2
統計的異常検出
      ↓
Level 3
特徴量 + 古典的機械学習
      ↓
Level 4
Deep Learning
```

重要なポイントは次の通り。

1.  高度なアルゴリズムほど優れているわけではない。
2.  物理的な異常条件が明確なら、しきい値が最適な場合がある。
3.  正常データのばらつきを利用するなら統計的手法が有効。
4.  時系列波形では「特徴量」という考え方が非常に重要。
5.  正常データが多く異常データが少ない設備では、Isolation
    Forestなどと相性が良い。
6.  十分な正常・異常ラベルがあるなら教師あり機械学習も利用できる。
7.  Deep
    Learningは、人間による特徴量設計では十分に検出できない複雑な波形異常で検討する。
8.  機械振動ではFFTなどの周波数解析が重要。
9.  SQLiteへの生波形保存は、将来の統計・機械学習・Deep
    Learning研究にも重要。
10. 現在のアプリを「異常判定アプリ」であると同時に「将来のAI用データ収集基盤」と考えることができる。

現在の `judge_data()` は小さな関数だが、将来的には、

``` text
設備データ受信
      ↓
特徴抽出
      ↓
異常検出
      ↓
OK / NG
      ↓
SQLite保存・画面表示・PLC通知
```

をつなぐ、このアプリの中核部分になる。

まずはモータ電流値やサーボトルク値の500点程度の波形から、最大値・平均値・RMS・標準偏差・Peak-to-Peakなどの特徴量を実際に計算するところから始め、その結果を見ながら統計、古典的機械学習、必要であればDeep
Learningへ段階的に発展させる方針が適している。
