# モータ電流値 受信アプリ

KEYENCE KV-5000の要求信号を常時監視し、3台のモータ電流値をCSVファイルへ保存するコンソールアプリです。

受信処理の並列実行には、`concurrent.futures.ThreadPoolExecutor`を使用しています。

## ファイル構成

```text
motor_current_receiver/
├── app.py
├── kv_com.py
├── requirements.txt
├── start.bat
├── motor1/
├── motor2/
└── motor3/
```

`motor1`～`motor3`フォルダは、アプリ初回起動時に自動作成されます。

## PLCデバイス

| モータ | PC受信要求 | 電流値 | PC受信完了 |
|---|---|---|---|
| motor1 | B10.0 | EM30000～EM31999 | B20.0 |
| motor2 | B10.1 | EM32000～EM33999 | B20.1 |
| motor3 | B10.2 | EM34000～EM35999 | B20.2 |

電流値は2Wordで1点とし、32ビット値を1000点受信します。

## 最初に変更する設定

`app.py`の次のIPアドレスを実機に合わせて変更します。

```python
PLC_IP_ADDRESS = "192.168.8.1"
```

## セットアップ

```bat
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

`kv_com.py`が別の共通環境ですでに管理されている場合は、同じフォルダに配置するか、Pythonからimportできる場所に配置してください。

## 起動

`start.bat`をダブルクリックします。

終了するときは、コンソールで `Ctrl + C` を押します。

終了操作を受け付けると、新規タスクの受付を停止し、実行中の受信・保存処理が完了するまで待ってから終了します。

## CSV形式

ファイル名の例：

```text
motor1_20260805_110425.csv
```

同じ秒に複数回保存された場合は、2個目以降に `_001` のような連番を付けて上書きを防止します。

CSV内容：

```csv
point_no,current_value
1,1234
2,1240
3,1238
```

## 処理の流れ

1. メインスレッドがB10.0～B10.2を順番に監視する。
2. OFFからONになった要求を1回だけ受け付ける。
3. `ThreadPoolExecutor`へ対象モータの受信タスクを登録する。
4. ワーカースレッドで32ビット電流値1000点を受信する。
5. 対応するフォルダへCSVファイルを保存する。
6. 保存成功後、B20.0～B20.2の対応ビットをONする。
7. PLCが要求・完了ビットをOFFする。
8. PCが要求ビットのOFFを確認すると、次回要求を受付可能にする。

## ThreadPoolExecutorを採用した理由

### 同時実行数を明確に制限できる

```python
self.executor = ThreadPoolExecutor(
    max_workers=len(MOTOR_CONFIGS),
    thread_name_prefix="motor-receiver",
)
```

モータ数と同じ3本を最大並列数としています。

要求のたびに無制限にスレッドを作成するのではなく、最大スレッド数が設計上明確になります。

### スレッドを使い回せる

`threading.Thread`を直接生成する方式では、要求のたびにスレッドを作成し、処理終了後に破棄します。

`ThreadPoolExecutor`では、用意されたワーカースレッドを繰り返し利用します。今回のように、同じ種類の受信処理が何度も発生するアプリに適しています。

### Futureで実行状態を管理できる

`executor.submit()`は、登録した処理を表す`Future`を返します。

```python
future = self.executor.submit(
    self._receive_and_save,
    config,
)
```

アプリではモータごとにFutureを保持し、次の条件で実行中か確認します。

```python
if future is not None and not future.done():
    return
```

これにより、同じモータの受信処理が実行中に、重複して新しい処理を開始することを防止できます。

将来はFutureを使って、次のような機能を追加できます。

- モータ別の実行状態表示
- 処理完了確認
- 例外確認
- 終了時の処理待ち
- 完了後の共通処理

### 終了処理を安全にしやすい

アプリ終了時は次の処理を実行します。

```python
self.executor.shutdown(
    wait=True,
    cancel_futures=True,
)
```

- 実行中の処理は完了まで待つ
- まだ開始されていない待機タスクはキャンセルする
- CSV保存中やPLC通信中の処理を途中で切りにくくする

`daemon=True`のスレッドを直接使う方式では、メインスレッド終了時に処理途中で終了する可能性があります。設備データ保存アプリでは、Executorで終了を管理する方が安全です。

## ThreadPoolExecutorを使わない方がよい場合

ThreadPoolExecutorが常に最適とは限りません。次のような場合は、`threading.Thread`を直接使う方が分かりやすいことがあります。

### スレッドごとに特殊な制御が必要な場合

- スレッドごとにdaemon属性を変える
- 各スレッドが独自の終了イベントを持つ
- 各スレッドが長時間常駐する
- スレッドごとに異なる監視ループを動かす
- スレッドの生成・終了を個別に厳密管理する

今回の受信処理は、要求ごとに開始して保存後に終了する短期タスクなので、ThreadPoolExecutor向きです。

### 処理が1回しか発生しない場合

一度だけ動かす処理では、スレッドプールを用意する利点が小さくなります。

今回のアプリでは受信要求が繰り返し発生するため、この条件には当てはまりません。

### 待機キューへ処理を蓄積したくない場合

`submit()`はワーカーがすべて使用中でも、処理を待機キューへ登録できます。

このアプリでは、モータごとのFutureと要求受付状態を確認し、同じ要求を繰り返し登録しないことで、タスクの蓄積を防止しています。

### 実行中スレッドを強制停止したい場合

`Future.cancel()`でキャンセルできるのは、原則としてまだ実行開始されていないタスクです。すでに実行中のスレッドを安全に強制停止することはできません。

途中停止が必要になった場合は、`threading.Event`などを使い、処理側が終了要求を確認して自分で終了する仕組みが必要です。これはThreadPoolExecutorでも`threading.Thread`でも同じです。

## PLC同時通信に関する注意

`kv_com.py`は通信のたびに新しいTCPソケットを作成するため、各ワーカースレッドは別の接続でPLCと通信します。

最大で次の通信が近接して発生する可能性があります。

- motor1のEMデータ読込み
- motor2のEMデータ読込み
- motor3のEMデータ読込み
- メインスレッドのB10.0～B10.2監視

実機では次の点を確認してください。

- KV-5000が同時接続を安定して処理できるか
- 3台同時受信時の応答時間
- 監視通信とEM読込みが重なった場合のPLC負荷
- 通信タイムアウトやエラーが増えないか

不安定になる場合は、次の順番で調整します。

1. `max_workers=3`のまま実機確認する。
2. 不安定なら`max_workers=2`へ減らす。
3. それでも不安定ならPLC通信全体をLockで直列化する。

PLC通信全体をLockすると安全性は上がりますが、受信処理は実質的に直列となります。最初からLockを入れず、実機結果を見て判断する方針です。

## 要求の二重受付防止

このアプリでは、次の2つを組み合わせています。

- `request_latched`：要求信号がOFFへ戻るまで再受付しない
- `Future.done()`：同じモータの処理が実行中なら再実行しない

要求信号がONのまま監視周期ごとに読み込まれても、同じデータを繰り返し保存しません。

## 注意事項

- 完了通知はCSV保存まで正常に完了した場合だけONします。
- 通信エラーまたは保存エラー時は完了通知をONしません。
- PC側は完了通知をOFFしません。PLC側で要求信号と完了信号をOFFしてください。
- 3台から同時に要求が来た場合、最大3本のワーカースレッドで受信します。
- `kv_com.py`は通信ごとにTCPソケットを生成するため、各スレッドの通信は別接続になります。
- Futureは実行状態管理に使用し、同一モータの重複タスク登録を防止します。
