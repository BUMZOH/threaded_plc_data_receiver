# Isolation Forest 設備異常検知プロジェクト

設備データから取得した `peak_value` と `rms` を特徴量として、Isolation
Forestで異常検知を行うためのプロジェクトです。

このプロジェクトは、大きく次の2つに分かれています。

-   `train_model.py`\
    正常データを使ってIsolation
    Forestを学習し、検証後にモデルと独自しきい値を保存する。
-   `anomaly_detector.py`\
    保存済みモデルとしきい値を読み込み、新しいデータを `OK` / `NG`
    判定する。

------------------------------------------------------------------------

## 1. プロジェクトの考え方

このプロジェクトでは、Isolation Forestの標準 `predict()`
を最終判定には使用しません。

Isolation Forestには、まず

``` python
model.score_samples(X)
```

で「どの程度異常らしいか」を計算させます。

その後、学習時に正常データから求めた独自の `threshold`
と比較して判定します。

``` text
新しい設備データ
        ↓
peak_value / rms
        ↓
Isolation Forest
        ↓
score_samples()
        ↓
score < threshold ?
        ↓
   Yes       No
    ↓         ↓
   NG        OK
```

役割としては次のように分けています。

``` text
Isolation Forest
    → 異常スコアを計算する

threshold
    → どこから異常扱いするかを決める
```

------------------------------------------------------------------------

## 2. 使用する特徴量

現在のモデルでは次の2特徴量を使用します。

  特徴量         内容
  -------------- -----------------------------------------
  `peak_value`   計測データのピーク値
  `rms`          RMS（Root Mean Square：二乗平均平方根）

学習時の特徴量は `threshold.json`
にも保存されるため、異常判定側では学習時と同じ特徴量・列順を利用できます。

# 5. `train_model.py`

## 5.1 役割

`train_model.py` は**モデル作成用プログラム**です。

主な処理は次のとおりです。

1.  `servo_torque.csv` を読み込む
2.  `judge == "OK"` の正常データだけを抽出する
3.  `measured_at` の時系列順に並べる
4.  正常データを学習80%・検証20%に分割する
5.  `peak_value` と `rms` でIsolation Forestを学習する
6.  学習正常データの `score_samples()` を計算する
7.  正常スコアの下位0.1%点から独自しきい値を決める
8.  未来側20%の正常データで誤検出率を確認する
9.  実NGデータを未知データとして評価する
10. 0.1%、0.5%、1%、2%、5%のしきい値候補を比較する
11. モデルとしきい値情報を保存する
12. 保存したモデルを再読込して動作確認する
13. 散布図とスコア分布を表示する

------------------------------------------------------------------------

## 5.2 学習データと検証データ

正常データをランダムには分割せず、`measured_at`
の古い順に並べて分割します。

``` text
過去                                      未来
│-------------------------------------------│
│              正常データ                   │
│-------------------------------------------│
│       学習 80%            │  検証 20%     │
│                           │               │
└──────── fit() ────────────┘   未知データ
```

設備データでは、

``` text
過去のデータでモデルを作る
        ↓
その後に発生したデータを判定する
```

という実運用に近い形で検証するためです。

------------------------------------------------------------------------

## 5.3 独自しきい値

現在の設定は、

``` python
THRESHOLD_PERCENTILE = 0.1
```

です。

学習正常データの異常スコアの**下位0.1%点**をしきい値として採用します。

判定ルールは、

``` python
score < threshold
```

なら異常です。

現在は0.1%を採用していますが、これは固定的な正解ではありません。今後NGデータが増えた場合は、異常の見逃しと正常データの誤検出の両方を確認して再調整します。

------------------------------------------------------------------------

## 5.4 モデルの保存

学習後、Isolation Forestモデルは次のファイルへ保存されます。

``` text
model/isolation_forest_model.joblib
```

保存には `joblib` を使用します。

``` python
joblib.dump(
    model,
    MODEL_PATH,
)
```

------------------------------------------------------------------------

## 5.5 しきい値情報の保存

モデルとは別に、

``` text
model/threshold.json
```

へ判定情報を保存します。

保存される主な内容は次のとおりです。

``` json
{
    "threshold": -0.750212,
    "threshold_percentile": 0.1,
    "features": [
        "peak_value",
        "rms"
    ],
    "train_ratio": 0.8,
    "train_count": 4189,
    "validation_count": 1048,
    "validation_false_positive_count": 1,
    "validation_false_positive_rate": 0.0954
}
```

数値は学習データによって変化します。

特に重要なのは、

``` text
threshold
features
```

です。

異常判定プログラムはこの情報を利用するため、学習時と判定時で特徴量やしきい値を合わせられます。

# 6. `anomaly_detector.py`

## 6.1 役割

`anomaly_detector.py` は**実際の異常判定を行うためのモジュール**です。

外部プログラムから基本的に使用する関数は、

``` python
predict_anomaly()
```

です。

------------------------------------------------------------------------

## 6.2 基本的な使い方

``` python
from anomaly_detector import predict_anomaly


result = predict_anomaly(
    peak_value=10,
    rms=5.40,
)

print(result)
```

------------------------------------------------------------------------

## 6.3 戻り値

`predict_anomaly()` は辞書を返します。

正常判定の場合のイメージ：

``` python
{
    "peak_value": 10.0,
    "rms": 5.4,
    "score": -0.45,
    "threshold": -0.75,
    "prediction": 1,
    "is_anomaly": False,
    "judge": "OK",
}
```

異常判定の場合：

``` python
{
    "peak_value": 35.0,
    "rms": 10.82,
    "score": -0.79,
    "threshold": -0.75,
    "prediction": -1,
    "is_anomaly": True,
    "judge": "NG",
}
```

### 戻り値の意味

  キー           内容
  -------------- --------------------------------------
  `peak_value`   入力したピーク値
  `rms`          入力したRMS
  `score`        `score_samples()` で求めた異常スコア
  `threshold`    学習時に決定した独自しきい値
  `prediction`   正常=`1`、異常=`-1`
  `is_anomaly`   異常なら `True`
  `judge`        `"OK"` または `"NG"`

------------------------------------------------------------------------

## 6.4 モデルは最初の1回だけ読み込む

モデル読込関数には、

``` python
@lru_cache(maxsize=1)
def _load_model():
```

を使用しています。

そのため、同じPythonプロセス内で、

``` python
predict_anomaly(...)
predict_anomaly(...)
predict_anomaly(...)
```

と繰り返し判定しても、モデルファイルとJSONファイルを毎回ディスクから読み込むことはありません。

``` text
最初の判定
    ↓
joblib / JSON 読込
    ↓
メモリに保持

2回目以降
    ↓
メモリ上のモデルを再利用
```

設備アプリから連続して判定する用途を考えた構成です。

------------------------------------------------------------------------

## 6.5 学習時と同じ特徴量を使う

判定側では `threshold.json` から、

``` python
features = model_info["features"]
```

を読み込みます。

その情報からDataFrameを作るため、学習時の特徴量名と列順を再利用できます。

``` text
学習時
peak_value + rms
        ↓
threshold.jsonへ保存
        ↓
判定時
同じ特徴量・同じ順番でモデルへ入力
```

------------------------------------------------------------------------

# 7. 実行方法

## 7.1 最初にモデルを作成する

まず、

``` bash
python train_model.py
```

を実行します。

正常データの学習・検証が行われ、正常に終了すると、

``` text
model/
├─ isolation_forest_model.joblib
└─ threshold.json
```

が作成されます。

`train_model.py`
を再実行すると、同じ保存先へ新しい学習結果が保存されます。

------------------------------------------------------------------------

## 7.2 異常判定モジュール単体テスト

モデル作成後、

``` bash
python anomaly_detector.py
```

を実行します。

ファイル末尾の、

``` python
if __name__ == "__main__":
```

にあるテストコードが実行されます。

現在のテストでは、

``` text
正常想定
peak_value = 10
rms        = 5.40
```

と、

``` text
異常想定
peak_value = 35
rms        = 10.82
```

の2件を判定します。

------------------------------------------------------------------------

## 7.3 他のアプリから使用する

実運用アプリでは、

``` python
from anomaly_detector import predict_anomaly
```

として読み込みます。

たとえば、

``` python
result = predict_anomaly(
    peak_value=12,
    rms=5.55,
)

if result["is_anomaly"]:
    print("異常候補です")
else:
    print("正常です")
```

のように利用できます。

# 9. 学習と実運用を分離する理由

設備アプリでデータを1件判定するたびに `fit()` を行う必要はありません。

学習はモデル更新時だけ行い、通常運用では保存済みモデルを使用します。

``` text
モデル作成時
    ↓
train_model.py
    ↓
学習・検証・保存


通常運用
    ↓
anomaly_detector.py
    ↓
保存済みモデルで高速に判定
```

この分離により、設備アプリ側の処理をシンプルにできます。

------------------------------------------------------------------------

# 10. 現在のモデルについての注意点

現在の学習データでは実NGデータが少ないため、下位0.1%のしきい値が将来のすべての異常に対して最適であるとはまだ断定できません。

現在のモデルは、

-   正常データを中心にIsolation Forestを学習する
-   正常データのスコア分布から独自しきい値を設定する
-   未知の正常データで誤検出率を確認する
-   実NGが検出できることを確認する

という初期モデルです。

今後データが蓄積されたら、特に次の点を再評価します。

-   NG見逃し件数
-   Recall
-   正常データの誤検出率
-   品種や設備条件による分布変化
-   時間経過による正常状態の変化
-   `threshold` の再調整
-   モデル再学習のタイミング

# 12. まとめ

このプロジェクトでは、**モデルを作る処理と、モデルを使う処理を明確に分離**しています。

``` text
train_model.py
    ↓
学習する
検証する
thresholdを決める
モデルを保存する


anomaly_detector.py
    ↓
モデルを読み込む
新しいデータを評価する
scoreを計算する
thresholdと比較する
OK / NGを返す
```

実運用アプリから見れば、機械学習の内部処理を毎回意識する必要はありません。

基本的には、

``` python
result = predict_anomaly(
    peak_value=peak_value,
    rms=rms,
)
```

と呼び出し、

``` python
result["judge"]
```

または、

``` python
result["is_anomaly"]
```

を確認すれば異常判定を利用できます。

この構成を、今後の設備異常検知アプリの基礎として使用します。
