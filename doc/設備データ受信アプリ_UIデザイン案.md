# 設備データ受信アプリ UIデザイン案

## 1. 目的

本資料は、設備データ受信アプリの機能実装がほぼ完了した段階で、今後のUI改善方針を明確にするためのデザイン案である。

現在のアプリは、PLC監視、CSV /
SQLite保存、リアルタイムグラフ表示、保存データの履歴表示など、主要な機能が実装されている。

今後は既存機能を大きく変更せず、HTML /
CSSを中心に画面構成と視認性を改善し、**現代的で見やすい設備監視アプリ**へ仕上げる。

------------------------------------------------------------------------

## 2. デザインの基本方針

目標とする方向性は、派手なWebサイトではなく、次のようなイメージとする。

> **Windows 11 + 現代的な管理ダッシュボード**

工場設備で常用するアプリであるため、装飾性よりも以下を優先する。

-   一目で現在の状態が分かる
-   操作箇所が分かりやすい
-   グラフを主役にする
-   長時間表示しても疲れにくい
-   色を使いすぎない
-   適度な余白を設ける
-   操作ミスを起こしにくい
-   将来の機能追加にも対応しやすい

------------------------------------------------------------------------

## 3. 画面全体のイメージ

``` text
┌─────────────────────────────────────────────┐
│ 設備データ 受信アプリ              ● 監視中 │
│ PLC 192.168.8.1                              │
├─────────────────────────────────────────────┤
│ 保存形式 [ SQLite ▼ ]  表示 [ Torque ▼ ]   │
│                                             │
│ [ 監視開始 ]   [ 監視停止 ]                 │
├─────────────────────────────────────────────┤
│ ToolB Cross Torque        2026-08-13 16:30  │
│ ┌─────────────────────────────────────────┐ │
│ │                                         │ │
│ │              Chart.js                  │ │
│ │                                         │ │
│ └─────────────────────────────────────────┘ │
│                                             │
│              |<   <   >   >|               │
└─────────────────────────────────────────────┘
```

画面は大きく次の3領域に分ける。

1.  ヘッダー / 状態表示
2.  設定・操作パネル
3.  グラフ・履歴表示

------------------------------------------------------------------------

## 4. ヘッダー / 状態表示

### 4.1 アプリタイトル

画面上部に

**設備データ 受信アプリ**

を配置する。

現在の単純な見出し表示から、アプリ全体のヘッダーとして扱う。

### 4.2 PLC IPアドレス

PLC IPアドレスはタイトル付近に補助情報として表示する。

例：

``` text
PLC  192.168.8.1
```

IPアドレスは重要な情報ではあるが、常時操作する項目ではないため、タイトルより小さく控えめに表示する。

### 4.3 監視状態

現在の「監視中」「停止中」という文字だけではなく、**ステータスバッジ**として表示する。

例：

``` text
● 監視中
● 停止中
```

色の候補：

-   監視中：緑系
-   停止中：グレー系
-   エラー発生時：赤系

状態を文字だけでなく色でも認識できるようにする。

ただし、色だけに依存せず必ず文字も表示する。

------------------------------------------------------------------------

## 5. 設定・操作パネル

現在縦方向に並んでいる設定項目を、ひとつの設定パネルとしてまとめる。

対象項目：

-   データ出力形式
-   グラフ表示対象
-   監視開始
-   監視停止

### 5.1 データ出力形式

現在の機能をそのまま使用する。

``` text
保存形式  [ SQLite ▼ ]
```

選択肢：

-   SQLite
-   CSV

監視中は現在と同様に変更不可とする。

### 5.2 グラフ表示対象

``` text
表示データ  [ ToolB_Cross_Torque ▼ ]
```

または画面幅に余裕があれば、

``` text
保存形式 [ SQLite ▼ ]    表示データ [ ToolB_Cross_Torque ▼ ]
```

のように横並びにする。

### 5.3 監視開始ボタン

監視開始は主要操作であるため、他のボタンより視認性を高くする。

例：

``` text
[ 監視開始 ]
```

デザイン：

-   塗りつぶしボタン
-   適度な角丸
-   十分なクリック領域
-   有効 / 無効状態を明確にする

### 5.4 監視停止ボタン

``` text
[ 監視停止 ]
```

開始ボタンと区別しやすいデザインにする。

停止操作であるため赤系も候補とするが、強すぎる警告色にはしない。

------------------------------------------------------------------------

## 6. グラフ表示エリア

このアプリの中心機能であるため、**グラフを画面の主役**として扱う。

現在のChart.jsによるグラフ描画機能はそのまま使用する。

### 6.1 グラフカード

グラフ全体を白背景のカード内に配置する。

イメージ：

``` text
┌────────────────────────────────────────────┐
│ ToolB_Cross_Torque       2026-08-13 16:30 │
│                                            │
│   ┌────────────────────────────────────┐   │
│   │                                    │   │
│   │              グラフ                │   │
│   │                                    │   │
│   └────────────────────────────────────┘   │
│                                            │
│               |<  <  >  >|                 │
└────────────────────────────────────────────┘
```

カードには次の要素をまとめる。

-   表示データ名
-   取得日時
-   Chart.jsグラフ
-   履歴移動ボタン

これにより、「今表示しているグラフに関する情報」がひとつの領域にまとまる。

### 6.2 表示データ名

現在の `表示データ:`
という独立した行ではなく、グラフカード上部に配置する。

例：

``` text
ToolB_Cross_Torque
```

グラフタイトルに近い役割として少し強調する。

### 6.3 取得日時

表示データ名と同じ行の右側などに配置する。

例：

``` text
ToolB_Cross_Torque            2026-08-13 16:30:25
```

リアルタイムPLC受信データと保存データの両方で同じ位置に表示する。

時刻はPC側でデータを受信したタイミングを使用する。

厳密なPLC測定時刻ではなく、**その波形がおおよそいつ取得されたものか確認するための時刻**として扱う。

------------------------------------------------------------------------

## 7. 保存データ履歴操作

現在の4ボタンは機能をそのまま維持する。

``` text
|<    <    >    >|
```

意味：

  ボタン   機能
  -------- ---------------
  `|<`     最古のデータ
  `<`      1つ前のデータ
  `>`      1つ後のデータ
  `>|`     最新のデータ

### デザイン方針

-   グラフカード下部中央に配置
-   現在より少しコンパクトにする
-   4つのボタンの大きさを揃える
-   適度な角丸を付ける
-   disabled状態を明確にする

監視中や「すべて」表示時に無効化する現在の制御は維持する。

------------------------------------------------------------------------

## 8. 配色方針

全体として色数を抑える。

### 基本色

-   画面背景：薄いグレー
-   カード背景：白
-   通常文字：濃いグレー
-   補助文字：中間グレー
-   境界線：非常に薄いグレー

### アクセントカラー

主要操作や選択状態だけに青系などのアクセントカラーを使用する。

### 状態色

-   正常 / 監視中：緑
-   停止中：グレー
-   異常 / エラー：赤
-   注意：必要になった場合のみ黄・橙

色を装飾目的で多用せず、**状態や操作の意味を伝えるために使用する**。

------------------------------------------------------------------------

## 9. 角丸・影・余白

「今風」に見せるためには色よりも、以下の要素を重視する。

### 角丸

カード、ボタン、select要素などに控えめな角丸を付ける。

極端に丸くせず、業務アプリらしさを残す。

### 影

カードには非常に薄い影を付け、背景との境界を表現する。

強いドロップシャドウは使用しない。

### 余白

現在より余白を広めに取り、

-   タイトル
-   設定
-   操作
-   グラフ
-   履歴操作

のグループを視覚的に分離する。

現代的なUIでは、罫線を大量に引くよりも**余白によって情報を整理する**。

------------------------------------------------------------------------

## 10. フォント方針

特殊なフォントの追加インストールは前提としない。

Windows /
WebView環境で自然に表示できる標準的なシステムフォントを使用する。

CSSではシステムUIフォントを優先する方向とする。

目的はデザイン性よりも、

-   読みやすさ
-   Windowsとの統一感
-   他PCへの展開の容易さ

を優先する。

------------------------------------------------------------------------

## 11. HTML / CSS / JavaScriptの役割

### HTML

UIの構造を整理する。

主な変更候補：

-   ヘッダー
-   設定パネル
-   グラフカード
-   情報表示領域
-   履歴操作領域

既存JavaScriptが参照している `id` は原則維持する。

### CSS

今回のUI改善の中心。

主に以下を担当する。

-   背景色
-   カード
-   レイアウト
-   ボタン
-   select
-   ステータス表示
-   余白
-   角丸
-   影
-   フォントサイズ

### JavaScript

既存機能はなるべく変更しない。

必要に応じて、

-   監視中 / 停止中のCSSクラス切替
-   状態に応じた表示変更

など、見た目に必要な最小限の処理のみ追加する。

### Python

UIデザイン変更では原則変更しない。

PLC通信、データ保存、履歴読み込みなどの既存ロジックをそのまま維持する。

------------------------------------------------------------------------

## 12. 既存機能を壊さないための方針

UI改造では、見た目と機能変更を同時に行わない。

特にJavaScriptが参照している以下のようなHTML要素の `id` は維持する。

-   `status`
-   `start-button`
-   `stop-button`
-   `save-mode-select`
-   `data-select`
-   `chart-data`
-   `measured-at`
-   `oldest-button`
-   `previous-button`
-   `next-button`
-   `latest-button`
-   `data-chart`

これによりHTMLの配置を変更しても、既存JavaScriptへの影響を最小限にできる。

------------------------------------------------------------------------

## 13. 改造手順

UIは一度にすべて変更せず、段階的に改造する。

### 第1段階：画面全体のレイアウト

-   body背景
-   main領域
-   最大幅
-   全体余白
-   基本フォント

まず「今風」の土台を作る。

### 第2段階：ヘッダー

-   アプリタイトル
-   PLC IPアドレス
-   監視状態バッジ

を整理する。

### 第3段階：設定パネル

-   SQLite / CSV
-   表示データ
-   監視開始 / 停止

をカードまたはパネルとしてまとめる。

### 第4段階：グラフカード

-   表示データ名
-   取得日時
-   Chart.jsグラフ

をひとつのカードにまとめる。

### 第5段階：履歴操作ボタン

4つの履歴ボタンを統一デザインにする。

### 第6段階：状態表示の動的デザイン

JavaScriptから監視状態に応じてCSSクラスを変更し、

-   監視中
-   停止中
-   エラー

を視覚的に分かりやすくする。

### 第7段階：細部調整

-   ボタンサイズ
-   selectサイズ
-   フォントサイズ
-   グラフ高さ
-   余白
-   disabled表示
-   hover表示

などを実際の画面を確認しながら調整する。

------------------------------------------------------------------------

## 14. 今回のUI改善で変更しないもの

UI改善の段階では、以下の機能ロジックは原則変更しない。

-   PLC監視処理
-   ThreadPoolExecutorによるデータ受信
-   CSV保存
-   SQLite保存
-   BLOB処理
-   Chart.jsへのデータPush
-   保存データ読み込み
-   最古 / 前 / 次 / 最新の履歴移動
-   PLC完了通知
-   アプリ終了処理

UI改善と内部ロジック変更を分離することで、不具合発生時の原因を特定しやすくする。

------------------------------------------------------------------------

## 15. 最終的な目標

本アプリは、単に「動作するPLCデータ受信プログラム」ではなく、

> **設備担当者が日常的に使用できる、シンプルで見やすい設備データ監視アプリ**

として仕上げる。

目指すUIは、

-   シンプル
-   現代的
-   視認性が高い
-   操作が直感的
-   工場設備アプリとして落ち着いている
-   メンテナンスしやすい

というバランスを重視する。

特にグラフを主役とし、設定や操作部分は必要以上に目立たせず、**「現在何を表示しているか」「いつ取得したデータか」「監視中かどうか」が一目で分かる画面**を最終形とする。
